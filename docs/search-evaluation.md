# 搜索效果与性能评测

本表是人工验收方案，不代表已经完成真实 API 测试。离线测试只验证参数、来源判定、错误与并发行为；真实调用需要显式启用并可能计费。

## 固定样本

| 类别 | 问题或输入 | 验收重点 |
| --- | --- | --- |
| 官方事实 | 从 DeepSeek 官方文档确认 Anthropic 接口地址 | 来源为官方页面，地址正确 |
| 时效信息 | 查询 DeepSeek 最近一次公开模型更新 | 同时核对发布日与事件日期，不把旧文当最新消息 |
| 版本限定 | 查询一个确定版本的公开软件迁移步骤 | 先固定软件及版本，不混用其他版本文档 |
| 交叉查证 | 比较两个明确版本的公开功能差异 | 区分独立来源与转载，未确认内容明确标注 |
| 精确网页 | 提供一篇带文章 ID 参数的公开文章 URL | 匹配该文章，不把首页或其他 ID 当目标 |
| 不可读取 | 提供需要登录或无法搜索到的 URL | 明确无法确认，不补写全文或结论 |
| 模糊问题 | 缺少地区或版本的查询 | 不随意假定地区和版本，明确限制 |

测试前固定具体问题、目标 URL 和核验依据；同一组比较不得临时改题。来源数量不是正确率，URL 命中也不是全文读取证明。

## 对比方法

1. 使用同一模型、密钥、工具版本、输出上限和时间范围，对比快速、标准、深入档位。分批测试并记录测试时段，不同时压测所有档位。
2. 每题重复至少三次，记录成功与失败、正确与否、目标 URL 命中、耗时和输入输出 token。失败也计入成功率，不只保留成功样本。
3. 分别统计正确率、成功率、耗时中位数和 P95。样本较少时 P95 仅作参考；只在成功答案中比较质量也要注明分母。
4. 性能另测冷连接、热连接、两个同会话相同并发请求、不同会话请求。区分排队耗时与上游服务波动，确认去重没有跨会话生效。
5. 只有质量不明显下降且延迟或 token 消耗改善时，才把某档位作为新的默认值。不要仅凭更低次数认定优化成功。

开启 `debug.log_raw_summary` 可记录请求标识、模型、结束原因、token、来源数量和总耗时。相同请求合并记录在调试日志中；不记录完整答案和请求正文。人工评分记录只留在本地，不提交私人查询或原始日志。

## 测试命令

离线验证：

```powershell
uv run pytest -q -m "not integration"
uv run python -m py_compile plugin.py
```

真实连通性测试需在环境中提供 `DEEPSEEK_API_KEY`，并显式设置 `RUN_DEEPSEEK_INTEGRATION=1` 后运行 `uv run pytest -q -m integration`。此测试要求非空正文、正常结束和真实搜索结果块，但仍不能代替上述人工质量评分。不要在仓库保存密钥。
